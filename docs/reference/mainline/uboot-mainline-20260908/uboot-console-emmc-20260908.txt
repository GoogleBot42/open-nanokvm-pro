Reading
======================================================================

* The COMMAND path works. The controller probes, both instances are listed,
  and the card is identified -- `mmc_init()` has to succeed before U-Boot
  tries to read the environment at all.
* The DATA path never completes. A 1 MiB env read and a ~650-byte FAT read
  fail the same way, so it is not transfer length.
* It is not ADMA: PIO reproduces it exactly.
* It is not "too fast": the conservative setting is the one that hangs rather
  than reporting a timeout. At 8-bit/HS/50 MHz the controller at least raises
  a clean data timeout; at 1-bit/legacy/25 MHz it stops responding.

That last asymmetry is the useful one. The `cdns,phy-input-delay-*` and
`cdns,phy-dll-delay-*` values in the device tree were taken from the vendor DT,
where they sit alongside a 1512-line fork of sdhci-cadence
(`sdhci_ax620e.c`). Section 11.10 predicted that fork was redundant because
mainline binds `cdns,sd4hc` unmodified -- it binds, it probes, it identifies
the card, and then it cannot move data. Whatever those 1512 lines do to the
PHY, some of it is load-bearing.
