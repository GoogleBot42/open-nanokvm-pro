Three things in that:

* SRS15 = 0x00000000 ON BOTH CONTROLLERS, read before U-Boot touches them.
  THE FIRST-STAGE LOADER DOES NOT SET SDHCI_CTRL_VDD_180. The 1.8 V seen on
  the running Linux is Linux's own switch, not something inherited. This is
  the answer rung 3 needs: promoting mainline U-Boot to slot A means the
  1.8 V switch has to happen in U-Boot, on the boot that reads the kernel.

* "Core: 17 devices, 12 uclasses" -- was 16/11 before. The fixed regulator
  bound.

* Six "failed to set vqmmc-voltage to 1.8V". Patch 0010 worked: the core did
  ask for 1.8 V, and sdhci_set_voltage()'s MMC_SIGNAL_VOLTAGE_180 arm did run.
  It then failed inside regulator_set_value() and returned before writing the
  bit -- because fixed_regulator_ops provides get_value, get_current,
  get_enable and set_enable, and no set_value at all. Asking a fixed rail for
  the level it is permanently sitting at is an error.
